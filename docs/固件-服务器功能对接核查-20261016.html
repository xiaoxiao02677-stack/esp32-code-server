结论与待办

❌ 未对接（5 项）

  • 配置版本检查 GET /ota/config/version —— 固件每次启动都会调用，目前稳定 404。需在 Java OTAController 补该端点（返回 {version, download_url}）。
  • 配置包下载 —— 依赖上一项，需一并提供配置下发文件服务。
  • OTA 固件包升级 —— ai_ota 表为空，设备无法收到真实升级 URL。需在后台「固件升级管理」上传四版型固件包并绑定 board type。
  • WS UDP 心跳端口 8002 —— 固件写死 8002，服务端无 UDP 监听。无害冗余；若要启用需在 8002 或改配置加 UDP 服务。
  • 动态字形推送 glyph_push —— 固件已具备字模下发能力且默认开启，服务端未实现生成/下发逻辑；属可选增强。

⚠️ 部分对接 / 需注意（4 项）

  • assets 资源包 OTA —— 上传/下载端点存在，但无任何 assets 记录，且 /yuhe/assets/download/* 返回 401。/otaMag/uploadAssetsBin 可直接复用，把这类文件放行到与 /ota 同级或更新路径。
  • 唤醒词覆盖行为 —— 服务端一旦下发设备级唤醒词，编译期默认「你好小禾」即失效。现有 3 台设备中已有 2 台下发了其它词，属预期还是误配需业务确认。
  • 唤醒词存储位置 —— ai_agent_wake_word 表 0 行，实际数据落在 ai_device_config.wake_word；两套入口并存，建议明确单一真源。
  • 固件副本与上游源码 —— hardware/sets/yuhe-esp32 与 hardware/small_screen_camera/yuhe-esp32 各自独立，改一处不会同步另一处。

⚪ 两端具备但未启用（3 项）

  • MQTT 通道 —— 固件实现完整，server.mqtt_gateway=null，OTA 不下发 mqtt 段。
  • UDP 网关 —— server.udp_gateway=null。
  • MCP 接入点 —— server.mcp_endpoint=null，外部工具市场未配置（设备端本地 MCP 工具不受影响）。
