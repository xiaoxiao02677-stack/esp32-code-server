## 1. 用户旅程

### 1.1 正常路径（Happy Path）：一次完整对话

普通用户视角，从上电到多轮对话：

1. **上电开机**：屏幕点亮、出现默认表情，自动连 Wi-Fi。
2. **唤醒**：说唤醒词"小智"或按下对话键 → 设备进入监听态（屏幕/LED 有"在听"提示）。
3. **提问**：用户说一句话（例："给我讲个笑话"）。
4. **思考**：说完后设备短暂停顿，表情变化（如"思考中"）。
5. **回复**：扬声器播出语音答复，用户**听得清、听得懂、内容与问题相关**；屏幕同步显示自己说的话（STT 回显）和回复字幕。
6. **结束**：播报完毕回到待听态，可以继续问下一句（连续多轮）。

用户感知成功的定义：**"我问了，它听懂了，它答了，答案对得上问题。"**

### 1.2 异常路径 A：服务器拒答（LLM 失败）

- 触发（测试注入）：将 LLM key 临时改为无效值/中文占位符（复现历史 bug），或让 LLM 上游超时。
- 用户看到：设备播报兜底话术，如"主人，小智现在有点忙"。
- 验收关注点：注入期间设备**不崩溃、不死机、有提示**（降级预期合理）；**恢复正常配置后，兜底话术必须完全消失**，且无需重启设备即可恢复对话。

### 1.3 异常路径 B：TTS 超时/失败

- 触发（测试注入）：临时禁用 EdgeTTS 通道或阻断其上游。
- 用户看到：屏幕有字幕（LLM 文本）但喇叭无声，或长时间无任何反应。
- 验收关注点：注入期间设备不死机、不无限等待；恢复后播报正常（有声有字幕）。**正常路径下"有字幕无声"出现即判失败。**

### 1.4 异常路径 C：网络断连

- 触发（测试注入）：断开 Wi-Fi/AP，或阻断 ws://sandyun.top:8001。
- 用户看到：设备给出可感知提示（屏幕/语音/表情），随后能自动恢复。
- 验收关注点：断网期间**不出现"假成功"**（不假装回答）；恢复后自动重连并恢复对话能力。

## 2. 判据表（按场景）

观测点来源三处：**设备串口日志**、**服务器日志**、**用户可感知**（屏幕/喇叭）。所有判据必须可观测、可复核。

### 场景 0：开机联网（前置）

| # | 通过判据 | 观测点 |
|---|---|---|
| 0.1 | 上电后 60s 内完成 Wi-Fi 连接与 WS 握手 | 串口日志 hello 握手成功；服务器日志 connection open |
| 0.2 | 屏幕显示正常默认表情（idle） | 用户可见 |

### 场景 1：正常对话（Happy Path）——核心场景

依据协议时序：`listen start → 上行音频帧 → {"type":"stt"} → {"type":"llm"} → {"type":"tts","state":"start"} → 下行音频帧 → {"type":"tts","state":"sentence_start"} → {"type":"tts","state":"stop"}`

| # | 通过判据 | 观测点 |
|---|---|---|
| 1.1 | 唤醒后进入 Listening，持续上传音频帧 | 串口日志 listen start + 二进制帧发送；服务器收到音频流 |
| 1.2 | ASR 正确：STT 文本回显与用户所说语义一致（允许个别错字，关键词必须命中） | 服务器下发 `{"type":"stt","text":"..."}`；设备屏幕回显 |
| 1.3 | LLM 有情绪反馈：收到 `{"type":"llm","emotion":"..."}`，屏幕表情更新 | 设备日志/屏幕表情变化 |
| 1.4 | TTS 生命周期完整：`tts start` → `sentence_start`（≥1 次，带 text）→ **下行音频帧数 > 0** → `tts stop` | 服务器日志 + 设备串口日志 |
| 1.5 | 用户听到语音：扬声器播出完整句子，与字幕一致，音量音色正常（XiaoxiaoNeural 女声） | 人耳 + 音频帧数 > 0 |
| 1.6 | 内容相关：LLM 回答与提问匹配（问"1+1"答"2"类），不是通用模板 | 字幕比对 / 用户判断 |
| 1.7 | **无任何失败标志话术**（见第 3 节清单） | 字幕（sentence_start text）与语音中均不出现 |
| 1.8 | 播完回到 Idle/Listening，**连续 ≥ 3 轮**重复以上全部通过 | 设备状态机回归待听态 |

体感时延要求（用户口径）：
- 说完话 → 听到回复首字：≤ 5s（P50 ≤ 3s 为佳）
- 播报句间卡顿：≤ 2s

### 场景 2：异常 A 服务器拒答（注入 → 恢复）

| # | 通过判据 |
|---|---|
| 2.1 | 注入无效 LLM key 后提问：设备播报兜底话术但**不崩溃、不死机**（降级行为本身合理，不算失败） |
| 2.2 | 恢复正确 key 后，**不重启设备**，下一轮对话即恢复正常（判据同场景 1.2–1.7） |
| 2.3 | 恢复后连续 3 轮无任何兜底话术 |

### 场景 3：异常 B TTS 超时（注入 → 恢复）

| # | 通过判据 |
|---|---|
| 3.1 | 禁用 TTS 后提问：设备不死机、不无限等待；有可感知提示或超时后返回 Idle |
| 3.2 | 恢复 TTS 后下一轮对话正常：tts start/sentence_start/stop 完整、音频帧数 > 0、有声有字幕 |
| 3.3 | 正常路径下出现"有字幕无声"或"有声无字幕" = 失败 |

### 场景 4：异常 C 网络断连（注入 → 恢复）

| # | 通过判据 |
|---|---|
| 4.1 | 断网后 30s 内设备给出可感知提示（屏幕/语音/表情），不死机、不无限重启 |
| 4.2 | 断网期间提问不出现"假成功"：不播兜底成功话术、不假装回答问题 |
| 4.3 | 网络恢复后 ≤ 60s 自动重连（WS 重新握手成功），恢复对话能力（判据同场景 1.2–1.7） |

## 3. 失败标志话术清单

历史背景：曾因 LLM key 为中文占位符，导致每次提问都播报"主人，小智现在有点忙"。**在正常路径（配置正确、网络正常）下，出现下列任一类话术即判 LLM/TTS 链路失败（一票否决）。**

| 类别 | 示例话术（含但不限于） | 判定 |
|---|---|---|
| 忙/稍后 | "主人，小智现在有点忙"、"我现在有点忙，稍后再说" | 失败 |
| 道歉/出错 | "抱歉，我出了点问题"、"对不起，我没听懂"、"出错了，请稍后再试" | 失败 |
| 服务不可用 | "服务暂时不可用"、"连接不上服务器" | 失败 |
| 通用兜底 | 用户已清晰提问却答"我没听清，请再说一遍" | 失败（ASR 归因） |
| 非中文默认回复 | 任何英文默认话术（"Sorry, I'm busy" 等） | 失败 |

识别方式（三条独立信号，任一命中即计入）：
1. 字幕（`sentence_start` 的 text）或播报语音中出现上表关键词；
2. 服务器日志出现 LLM 报错 / 走入 fallback / 默认回复分支；
3. **同一句兜底话术对任意不同问题都出现**（回答内容与问题无关）——强失败信号。

边界澄清（避免误判）：
- 异常注入场景（场景 2/3/4）中出现提示属**预期降级**，不算失败；但**注入条件移除后仍出现 = 失败**。
- 用户问题本身含"忙/抱歉"等字眼、且回答内容与问题相关时，不算兜底话术（以内容相关性为准）。

## 4. GATE 判定标准："普通用户可用"

GATE 通过须**同时**满足 4.1、4.2、4.3 全部条件（数据来自任务 #3–#9 的验证结果）。

### 4.1 通道级（输入：任务 #3 LLM、#4 TTS、#5 ASR、#6 WS）

| 通道 | 通过条件 |
|---|---|
| LLM（DeepSeek） | 调用成功率 ≥ 95%（采样 ≥ 20 次），无鉴权/占位符错误 |
| TTS（EdgeTTS） | 合成成功率 ≥ 95%，单句合成耗时 ≤ 5s，音色确为 zh-CN-XiaoxiaoNeural |
| ASR（FunASR） | 标准语料 10 句，关键词识别准确率 ≥ 90% |
| WS 网关 | 握手成功率 100%（≥ 10 次），会话保持 ≥ 10 分钟无断开 |

### 4.2 端到端（输入：任务 #8 模拟普通用户全链路测试）

- 场景 1 正常对话：≥ 10 轮提问，判据 1.1–1.8 **全部通过，通过率 100%**；
- 首响延迟：说完 → 听到回复首字，P50 ≤ 3s 且 P95 ≤ 5s；
- 失败标志话术：正常路径出现次数 = 0；
- 异常场景 2/3/4：全部判据通过，注入移除后均自动恢复（无需重启）。

### 4.3 一票否决项（任一出现即 GATE FAIL）

1. 正常路径出现任何失败标志话术（第 3 节清单）；
2. 正常路径出现"有字幕无声"或"有声无字幕"；
3. 设备死机、无限重启、无限等待（任何场景下）；
4. 异常条件移除后，设备无法自动恢复对话（需人工重启才算恢复）。

### 4.4 判定输出

- **GATE PASS** → 放行任务 #11（固件源码更新）；
- **GATE FAIL** → 输出失败判据编号清单，按判据回溯归因通道（LLM/TTS/ASR/WS），修复后重跑对应验证任务再判定。
