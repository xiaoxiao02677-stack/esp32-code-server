## 1. 用户类型枚举与判定逻辑

### 1.1 判定函数（优先级从上到下）

```
resolveUserType(info):            // info = userState.value，来源 cc_user_info（/user/info 补全后）
  if (info == null)                          → UNKNOWN   // 旧登录态/接口未返回
  if (username.toLowerCase() === 'demo')     → DEMO      // 公开展示账号（DB super_admin=1，无角色映射）
  if (Number(superAdmin) === 1)              → SUPER_ADMIN
  if (roles 含 'super_admin' 或 'admin')      → ADMIN
  else                                       → NORMAL
```

| 类型 | 判定依据 | 数据来源可靠性 |
|---|---|---|
| SUPER_ADMIN（超级管理员） | `superAdmin === 1` | 生产 jar 登录 TokenDTO **缺此字段**（写入 0）→ 依赖 /user/info 兜底（**待 a2 实测**） |
| ADMIN（管理员） | roles 数组含 super_admin/admin | 同上，TokenDTO 缺 → 依赖 /user/info |
| NORMAL（普通用户） | 以上均否 | 默认值即安全侧 |
| DEMO（展示账号） | `username.toLowerCase() === 'demo'` | username 两源都有（TokenDTO 或登录表单回填），**不依赖 superAdmin**，最稳 |
| UNKNOWN | info 为 null | 旧登录态（有 cc_token 无 cc_user_info）或 /user/info 未返回 |

### 1.2 DEMO 特例意图解读（含依据）

**解读**：demo 是公开展示账号——默认进游客页（/customer）体验，但**保留「→ 管理员视图」切换按钮**（因其 DB super_admin=1，需要能切到管理端演示）。

**依据**：
1. 用户原话前半句「demo用户登录之后，默认进入游客页面」是**陈述现状无抱怨**（V1/V2 登录本来就固定推 /customer）→ 保留默认游客页。
2. 后半句「但是没有按钮切入到游客端了」字面是"切到游客端"，但 demo 已在游客页、无此需求；结合 V2 代码实况——按钮 `v-if=canSwitchRole`，生产 TokenDTO 缺 superAdmin/roles → `hasAdminRole=false` → **「→ 管理员视图」按钮对 demo 消失**——用户真正缺的是切去**管理端**的按钮。缺陷机制与症状吻合。
3. 反证另一解读（"管理端缺切回游客端的按钮"）：V2 中 `/admin` 页面按钮条件 `role==='admin' || …` 对任何进入者恒真，该场景不存在缺陷 → 排除。

**风险标注**：此解读为高置信推断（机制吻合），但存在措辞歧义。若上线后用户反馈意图相反（demo 不给看管理端），只需把 DEMO 行的按钮格改为「隐藏」，不影响其他格子。

## 3. 边界规则

| # | 场景 | 规则 |
|---|---|---|
| R1 | **cc_user_info 为空**（旧登录态：有 cc_token 无 cc_user_info） | main.js 启动时 `if (getToken()) refreshUserInfo().catch(()=>{})` 异步补全；补全完成前按 UNKNOWN 处理（矩阵第 5 行）；补全后 userState 响应式更新，按钮自动出现/保持隐藏 |
| R2 | **/user/info 请求失败**（网络异常/5xx） | refreshUserInfo 静默返回 false，沿用 localStorage 旧值（demo/超管若旧值也缺 → 按钮暂缺、默认路由落 /customer，安全侧）；下次路由跳转不重试，刷新页面会重试 |
| R2b | **/user/info 返回 401** | api.js 判定 isAuthCheck=true → clearToken()（清 cc_token + cc_user_info + 重置 userState）→ 踢回 /login 重新走分流；有 10s 新鲜 token 竞态豁免 |
| R3 | **/user/info 返回 superAdmin=null** | merged 归一化 `Number(null)===1 ? 1 : 0` → 0 → 按无管理权限处理。**这是生产链路的核心风险点**：demo 与超管在生产若拿不到 superAdmin=1，矩阵中「默认 /admin + 按钮显示」两格全部失效（被压成 /customer + 隐藏）|
| R3b | **R3 发生时的 demo 兜底（建议必加）** | 按钮条件追加 `|| isDemoUser(userState)`——demo 按 username 判定、不依赖 superAdmin 字段，保证展示账号永远能切管理端。一行改动 ×2 组件（TopBar canSwitchRole / DockNav canSwitchToAdmin）。defaultRouteAfterLogin 不变（demo 本来就落 /customer，不受影响）|
| R4 | **demo 改密码后** | isDemoUser 按 username 判定 → 特例不变，仍默认 /customer + 保留按钮。mustChangePwd=1 流程：Login.vue 提示后 reload → App.vue onMounted checkForcePwd 弹全局强制改密窗 → 改完继续按 demo 分流 |
| R5 | **大小写 Demo/DEMO** | isDemoUser 内 toLowerCase() → 命中特例 |
| R6 | **守卫 fail-open 缺口（V3 已知问题，建议修）** | `if (info && !hasAdminRole(info)) return '/customer'`——info=null（UNKNOWN）时放行 /admin。旧登录态普通用户可浏览管理端 UI 直到下一次导航被拦截；API 层有服务端 403 兜底无数据泄露，但体验不佳。建议：守卫改 async，info=null 时 `await refreshUserInfo()` 后再判（一次请求代价换正确性）|
| R7 | **token 中途过期** | startTokenCheck 30s 轮询 → isTokenExpired → clearToken（三清）→ 踢 /login → 重新登录重走分流 |
| R8 | **登录响应新后端带权威角色** | login() 同步写 userState（不等 refreshUserInfo），新后端下按钮/分流即时生效；refreshUserInfo 再补全为幂等覆盖 |

## 4. 数据流设计

### 4.1 登录时序（V3 已实现）

```
用户提交登录
  │ authApi.login()
  ├─ setToken(cc_token)                       // TokenDTO + loginAt（401 竞态防护）
  ├─ 写 cc_user_info（username / superAdmin 缺省0 / roles 缺省[]）+ userState ← 同步响应式
  ├─ mustChangePwd===true ? 提示 → reload → App.vue 强制改密弹窗（结束流程）
  ├─ await refreshUserInfo()                  // GET /user/info 兜底补全 → 写回 cc_user_info + userState
  ├─ target = defaultRouteAfterLogin()        // demo→/customer；超管/admin→/admin；其余→/customer
  └─ router.push(target) + 300ms hash 双保险  // 防 router 时序卡 login 页
```

### 4.2 启动时序（刷新页面/老登录态）

```
main.js 模块加载
  ├─ userState = ref(getUserInfo() || {username:'', superAdmin:0, roles:[]})
  ├─ if (getToken()) refreshUserInfo().catch(()=>{})   // 异步补全，不阻塞首屏
  └─ 守卫按当前 userState 判定（UNKNOWN 安全侧）
```

### 4.3 伪代码签名（lib/api.js，V3 已实现；组件订阅方式）

```js
// 状态（单一事实源，响应式）
export const userState = ref(getUserInfo() || { username: '', superAdmin: 0, roles: [] })

// 判定
export function isDemoUser(info = userState.value): Boolean
//   String(info.username).toLowerCase() === 'demo'
export function hasAdminRole(info = userState.value): Boolean
//   Number(info.superAdmin) === 1 || roles.some(r => r==='super_admin' || r==='admin')

// 路由决策
export function defaultRouteAfterLogin(): '/admin' | '/customer'
//   isDemoUser() → '/customer'          （特例优先）
//   hasAdminRole() → '/admin'
//   else → '/customer'

// 身份补全（幂等；失败静默 false 不 throw）
export async function refreshUserInfo(): Boolean
//   GET /user/info → merged{username, superAdmin:0|1, roles[]} → localStorage + userState → true
//   无 token → false；异常 → false

// 组件侧（TopBar / DockNav，V3 已改为订阅响应式，不再裸读 localStorage）
const canSwitch = computed(() => {
  const u = userState.value
  if (!u) return false
  return hasAdminRole(u) /* + R3b: || isDemoUser(u) */
})
```

**要点**：按钮组件**禁止**直接调 getUserInfo()（读 localStorage 无响应式依赖，登录/补全后不会触发重算——这正是 V2 bug 的根因）；一律订阅 userState。
