## 1. 本轮最重要的发现：摄像头 XCLK 接在 NC 脚

| | 旧值 | 原理图 | 新值 |
| --- | --- | --- | --- |
| `CAMERA_PIN_XCLK` | `GPIO_NUM_5` | **GPIO5 = NC（未连接）**，XCLK 网络为 `IO12_DVP_XCLK` → GPIO17 | `GPIO_NUM_17` |

**为什么它是 0x106 的第一根因**（已在源码里逐行核实）：

```
driver/esp_camera.c:303   err = cam_init(config);        ← 先：初始化 LCD_CAM / XCLK
driver/esp_camera.c:310   err = camera_probe(config,…);  ← 后：才开始 SCCB 探测
target/esp32s3/ll_cam.c:414  gpio_matrix_out(config->pin_xclk, CAM_CLK_IDX, false, false);
driver/esp_camera.c:100-101  // LCD_CAM module of ESP32-S3 will generate xclk
                             #define CAMERA_ENABLE_OUT_CLOCK(v)   ← S3 上为空宏
```

即：**SCCB 探测开始时 XCLK 已经在输出**；而旧配置把它输出到原理图上的 NC 脚，
传感器拿不到工作时钟 → SCCB 从机不回应 → 17 个候选地址全 NACK →
`Detected camera not supported` + `0x106 (ESP_ERR_NOT_SUPPORTED)`。
这与实机日志完全吻合。

补充：S3 的 XCLK 走 GPIO 矩阵（`CAM_CLK_IDX`），**任意输出脚都合法**，改到 GPIO17 无需其它配合。

## 3. 原理图确认"不用改"的部分（避免被误改）

| 模块 | 结论 |
| --- | --- |
| TFT SPI | MOSI 40 / SCLK 41 / DC 39 / BL 42 —— 与代码一致，不动 |
| **LCD_CS** | 原理图备注原文：「LCD_CS：IO 扩展芯片输出，非 ESP32-S3 原生 GPIO」→ **bit0 = LCD_CS，低电平选通，稳态 0**，上一轮修复方向正确 |
| 背光极性 | 维持 `DISPLAY_BACKLIGHT_OUTPUT_INVERT = true`（P 沟道，栅极 R21 上拉 3V3，拉低导通） |
| 音频 ADC 地址 | 原理图写 ES8720 @0x41(7-bit)；代码 `AUDIO_CODEC_ES7210_ADDR 0x82` = 8-bit 写地址 = **0x41** → **地址本来就一致，不要改**，只有芯片型号名不同（驱动仍用 ES7210） |
| IO 扩展 | 原理图型号 PCF8557PW，与 PCA9557 同族同寄存器语义（0x00 输入/0x01 输出/0x02 极性/0x03 方向）；扫描在 0x19 有 ACK。**宏名 `AUDIO_CODEC_USE_PCA9557` 是构建开关，不要改名** |
| I2C / I2S | 全部一致 |

## 4. ⚠ 唯一待确认项：DVP_D2

原理图的 DVP 表里只出现 **D0 / D1 / D3 / D4 / D5 / D6 / D7**，**没有 D2**。
代码暂取 **GPIO10**（4~18 连续段里唯一既未被占用、又避开 USB 19/20 与 I2S 12/13/14 的空脚）。

- **D2 不参与 SCCB 探测** —— 即使猜错也**不会**导致 0x106，只影响图像位序（颜色/条纹异常）。
- 拿到原理图后只需改 `config.h` 的 `CAMERA_PIN_D2` 一行。

## 5. 编译后日志判读

**屏幕侧（预期已修复）**

```
PCA9557 bit0 (LCD_CS / reset-release, active-low) = 0 (selected): out=0x.., in=0x..
```
屏应出现**白底**（`SpiLcdDisplay` 构造会满屏填 0xFFFF）。
若仍全黑 → 查 §3 的 CS/背光两条，以及 `DISPLAY_SPI_MODE` 改 0 + `DISPLAY_SPI_HZ` 降到 40MHz 试一次。

**摄像头侧（本轮重点）**

```
Camera power on: PCA9557 bit2(DVP_PWDN, active-low)=0, camera SCCB candidates matched: N
```
- `N >= 1` 且出现具体型号（如 `OV2640` / `GC032A`）→ ✅ 探测通过，`camera=ready`
- 仍 `0x106` → 排线/焊接/模组供电；此时再看 `ScanI2cBus` 打印的总线设备清单：
  若连 0x18/0x19/0x41 之外**一个都没有**，说明摄像头确实没上电或没接上（硬件侧），
  与引脚配置无关。

**触摸**：本屏 FPC 无 SDA/SCL/INT 线 → 6 个候选地址全 NACK **属正常**，不是故障。
若全部 NACK，代码会自动穷举 PCF8557 低 4 位找 0x38 / 0x6A 挂在哪个电源域，看
`ScanPowerDomainsFor` 的打印即可。

## 6. 屏幕仍全黑时的定位自检（已内置，默认开启）

> **第 7 轮实机结果：阶段 1「全程没有变化」。**
> 这条结果**排除了背光极性** —— 极性接反也会闪（只是明暗颠倒），毫无变化说明
> GPIO42 的 PWM **根本没驱动到背光**。剩余可能只剩三种：
> ① GPIO42 不是背光脚  ② 背光由 PCF8557 某一位使能  ③ 屏/背光根本没电。
> **自检已切到阶段 2（`LCD_PROBE_PHASE 2`）扫这三类，请重新编译烧录。**

摄像头已修好后（日志出现 `Detected GC0308 camera` / `Camera ready`），屏幕仍全黑时启用。

**为什么必须靠肉眼**：本屏**没有 MISO** → 读不到屏 ID，软件无从判断 SPI 是否真通；
而 CS 若没选中，屏会一直停在睡眠（`0x11 SLPOUT` 根本没收到），**背光再亮也是全黑**，
与"背光坏了"在日志上**完全无法区分**。显示代码已与上游 pristine 逐行 diff 过，实质一致，
所以问题只剩两个：**背光不受控** 或 **CS 位不对**。

`config.h` 两个开关（默认 `1` / `0`）：

```c
#define DISPLAY_PROBE_ENABLED   1   /* 定位后改回 0 */
#define LCD_CS_PCA9557_BIT      0   /* 自检结果出来后改成真实位号 */
```

开机后自检做两件事，**全程约 20 秒，请盯着屏幕看**：

- **A. 背光自检** —— 在 100% / 0% 之间闪 2 次（每次 800ms）。观察有无明暗变化（全黑也会有底光变化）。
- **B. CS 位扫描** —— 把 PCF8557 的 bit0~bit7 **逐个单独拉低**，每次全屏填一种颜色并停 1.5s，
  且每个候选位都重跑一遍完整 init（否则该位若真是 CS，屏之前睡过去了也显示不出来）：

| 位 | 颜色 | 位 | 颜色 |
| --- | --- | --- | --- |
| bit0 | 红 RED | bit4 | 青 CYAN |
| bit1 | 绿 GREEN | bit5 | 品红 MAGENTA |
| bit2 | 蓝 BLUE | bit6 | 白 WHITE |
| bit3 | 黄 YELLOW | bit7 | 橙 ORANGE |

**判读**

| 现象（阶段 1） | 结论 | 处理 |
| --- | --- | --- |
| 出现过某个颜色（如绿色） | CS = 该位（如 bit1） | 把 `LCD_CS_PCA9557_BIT` 改成该位号，`DISPLAY_PROBE_ENABLED` 改回 0 重编译 |
| 全程无颜色，但 A 段有明暗变化 | 背光受控、CS 不在 bit0~7（或屏没供电） | 查 AU_3V3 屏电源 LDO 与排线 |
| **A 段也毫无明暗变化（本次实机结果）** | **背光不受控 → 排除极性** | **转阶段 2：`LCD_PROBE_PHASE` 改 2（已改好）** |

### 6.0 ⚠ 阶段 1/2 的方法缺陷（已修正，务必知道）

`Pca9557` 构造函数写的是 `WriteReg(0x03, 0xF8)` —— 方向寄存器 **1 = 输入（高阻）**，
即 **bit3~bit7 是高阻**。对高阻引脚写输出寄存器**完全无效**，
所以阶段 1「扫 bit0~bit7」实际上**只驱动了 bit0/1/2**，扫不出任何东西是必然的，
**不代表那些位没用**。

再加上用户确认「**刷机前屏幕能显示**」→ 硬件完好、出厂固件能点亮
→ 结论：有我们没驱动起来的脚。**阶段 3 就是先把方向全开再穷举。**

### 6.1 阶段 2：背光通路扫描

先全屏填白（这样一旦背光被点亮就是**白屏**，比"底光"好认），全程约 30 秒，盯屏幕看：

1. **GPIO 直驱扫描** —— 依次把候选脚 `低 1.2s / 高 1.2s`：
   `GPIO42(当前)` → `GPIO46` → `GPIO47` → `GPIO3` → `GPIO5(NC)`。
   直接用电平驱动，绕开 LEDC，可同时验证"是不是 LEDC 没配起来"。
2. **PCF8557 位使能扫描** —— 逐个把 bit0~bit7 **单独拉高** 1.2s，再全低 1.2s。

| 现象（阶段 2） | 结论 | 处理 |
| --- | --- | --- |
| 测某个脚/某一位时出现白屏 | 那就是背光脚 / 背光使能位 | 告诉我，或自行改 `DISPLAY_BACKLIGHT_PIN`（或把使能位加进初始化） |
| **全程依旧毫无变化** | **硬件供电或排线问题** | 按下节三条用万用表量 |

### 6.2 阶段 3：PCF8557 全脚穷举（当前生效，`LCD_PROBE_PHASE 3`）

新增 `Pca9557::SetDirection()`，自检里先把输出寄存器清 0，再 `SetDirection(0x00)`
（**8 个脚全部改成输出**），然后全屏填白并穷举，全程约 35 秒：

1. **两个极端组合**：`out=0x00`（全低）4s → `out=0xFF`（全高）4s。
   只要背光是 PCF8557 任一位控制（不管高有效还是低有效），这两个必有一个点亮它。
2. **逐位**：每位先 `单独高` 1.5s，再 `单独低` 1.5s（bit0~bit7 共 16 个状态）。

| 现象（阶段 3） | 结论 | 处理 |
| --- | --- | --- |
| 某个组合出现白屏/底光 | 该位就是背光或 CS | 告诉我组合值（如 `out=0x20`），我据此改正式初始化 |
| **全程依旧毫无变化** | 屏的 CS / 背光**不在 PCF8557 上** | 核对 TFT 接口的 SPI 引脚（40/41/39）与背光脚（42）是否适用于本板 |

### 6.3 若阶段 3 仍无变化 —— 核对这几项

1. 屏 FPC 排线是否插好 / 插反 / 虚焊 —— **AU_3V3 屏电源与 LEDA/LEDK 背光都走这个座子**，
   座子没接好会同时导致"屏不亮 + 背光不亮"，正好就是现在的现象。
2. 万用表量屏座上 **AU_3V3 对地是否有 3.3V**（ME6217C33M5G 专供 TFT，与系统 3V3 是两路独立 LDO）。
3. 量 **LEDA / LEDK** 两端电压，确认背光回路有电（Q2 栅极经 R21 10k 上拉 3V3 → P 沟道 → 拉低导通）。

自检结束会自动恢复正常输出（bit0=0 / bit1=1 / bit2=0）并全屏填白，不影响后续开机流程。

## 7. 顺带空出的 GPIO

DVP 改走 4/6/7/8/9/10/11/15/16/17/18/21 后，**GPIO3（原理图=用户按键）与 GPIO46 已无任何占用**。
若要恢复音量键，只能接这两个脚，接别的会撞 DVP。
