## 一、各 Bug 修复详情

### Bug-1：Abort 后解码包积压（P0）✅
**文件**：`main/application.cc` — `Application::AbortSpeaking()`

**根因（比报告更深入）**：调查报告推测"audio_service.cc:1429 跳过播放但包仍入队"，实际排查发现本仓库的下行路径已有 `generation` 检查（audio_service.cc:666：`generation != playback_generation_` 直接丢弃）——包不会积压。**真正的问题是**：`AbortSpeaking()` 只发服务器命令+置 `aborted_`，不清本地缓冲；auto 模式打断后 `HandleStateChangedEvent` 的 Listening case 若队列未 drain 会走 `pending_listening_start_` **等待旧回复自然播放完**（最多 ~1.2s 尾音）才进监听。

**修复**：`AbortSpeaking()` 中 `Schedule([this]{ audio_service_.ResetDecoder(); })`——立即清空本地解码/播放缓冲、`++playback_generation_` 并触发 `MAIN_EVENT_PLAYBACK_DRAINED`，使 pending 监听即时满足。ResetDecoder 幂等、内部有 mutex 保护，经 Schedule 回主循环执行保证线程安全。

### Bug-2：kDeviceStateFatalError 无 UI（P0）✅
**文件**：`main/application.cc` — `HandleStateChangedEvent` switch 新增 case（1225-1234）
**修复**：`SetStatus(FATAL_ERROR)` + `SetEmotion` + `SetChatMessage` + 停止语音/唤醒词（终态防御）。
**排查结论**：`kDeviceStateFatalError` 全仓库无设置路径（仅枚举定义+状态机终态），此 case 为防御性兜底。
**新增文案**：`Lang::Strings::FATAL_ERROR = "系统错误，请重启设备"`

### Bug-3：kDeviceStateAudioTesting 无 SetStatus（P0）✅
**文件**：`main/application.cc`（1209-1214）
**修复**：`case kDeviceStateAudioTesting` → `SetStatus(AUDIO_TESTING)` + `SetEmotion("neutral")`；特意不禁用语音处理（该状态本身在测试麦克风）。
**新增文案**：`Lang::Strings::AUDIO_TESTING = "音频测试中..."`

### Bug-4：配网模式网络图标延迟 10s（P1）✅
**文件**：`main/boards/common/wifi_board.cc` — `EnterWifiConfigMode()`
**修复**：两处 `StartWifiConfigMode()` 后加 `GetDisplay()->UpdateStatusBar(true)`（延迟任务分支 + Starting 同步分支），网络图标立即切换到 WIFI 图标，不影响通知浮层。

### Bug-5：断网后协议状态未重置（P1）✅
**文件**：`main/application.cc` — `HandleNetworkDisconnectedEvent()`
**修复**：移除"按状态 CloseAudioChannel"逻辑，统一 `ResetProtocol()`。安全性评估：经 Schedule 主循环执行、`IsAudioChannelOpened()` 守卫无双重关闭、不触碰状态机、重连路径无条件重建 protocol_、所有使用点有 null 守卫。

### Bug-6：Upgrading/Activating 无 SetStatus（P1）✅
**文件**：`main/application.cc`（1215-1224）
**修复**：`case kDeviceStateUpgrading` → `SetStatus(UPGRADING)`；`case kDeviceStateActivating` → `SetStatus(ACTIVATING)`。仅补状态栏文字，不破坏既有 SetChatMessage 进度/激活 UI 路径。
**新增文案**：`Lang::Strings::ACTIVATING = "激活中..."`（UPGRADING 已有）

### Bug-7：SetPreviewImage 空实现（P2）✅
**文件**：`main/display/lvgl_display/lvgl_display.cc`（309-409）
**修复**：实现完整预览图显示——全屏半透明遮罩 + `lv_image` 等比缩放居中（80%×80% 上限 100%），overlay 文件级静态管理（新预览替换旧的），`LV_EVENT_DELETE` 回调释放 `LvglImage` 所有权防悬垂。调用点：MCP `screen.preview_image`、相机预览（`esp32_camera.cc`/`esp_video.cc`/`sscma_camera.cc`）——之前 big screen 上静默无效，现已真实显示。

## 二、编译环境修复（额外发现）

**问题**：`build.py bigscreen-s3` configure 阶段 FATAL——
```
ESP_VIDEO_USE_CUSTOMIZED_ESP_H264_VERSION, introduced by espressif/esp_h264, defined in (unknown)
```
**根因（深度排查 6 轮）**：此错误**不是代码问题**。组件管理器的"新版本检查"（`check_for_new_component_versions`）会试探性 resolve 最新版组件，而 **registry 上 esp_video 2.5.0**（本地为 2.4.1）的 esp_h264 依赖带 `matches: $CONFIG{ESP_VIDEO_USE_CUSTOMIZED_ESP_H264_VERSION} == False`；esp32s3 构建时 esp_h264 是 p4-only 可选依赖（未安装、Kconfig 无此变量），sdkconfig.json 无该键 → `if_parser` 抛 `MissingKconfigError` → 组件管理器 exit(10) → CMake 重试 2 次后 FATAL。10月9日构建成功是因为当时 2.5.0 尚未发布。
**修复**：`IDF_COMPONENT_CHECK_NEW_VERSION=0`（关闭新版本检查，不影响 lock 锁定版本），已写入：
- `build-bigscreen.bat`（正式一键构建）
- `build_verify_bigscreen.bat`
- `build_fix_verify.bat`（本次验证用，无 pause 版）

**排查过程中临时修改了 venv 库 `idf_component_tools/debugger.py` 加调试打印，已还原原样。**
