# flash.py 新增「idf.py 快速烧录」模式（2026-10-17）

## 需求

> 「flash 新增一个功能，就直接使用 idf.py 的工具快速烧录。用项目里边的 build 目录去烧录。
> 这样也方便 省事 安全 不容易出问题。交互式让用户选择。」

## 做了什么

`hardware/sets/flash.py` 现在有两种烧录方式（新增 `--mode`，交互式终端不给参数时弹菜单）：

| 方式 | 实现 | 特点 |
|---|---|---|
| `idf`（菜单 1，回车默认） | 标准接线 → 真的 `idf.py -p <port> -b <baud> -B build flash`；反相接线 → 等价的单会话 `esptool write-flash` | 一条命令读完 `build/flash_args`，连一次会话，最省事 |
| `staged`（菜单 2，默认） | 逐段 + 1MB 切块 + 探活 + 自愈 | 链路不稳时用，断了只补那一段 |
| `diag`（菜单 d） | 调 `diag.py` 只读体检 | 不改 flash，只取证 |

两种方式共用同一套闸门：烧录前核对「写入地址 vs 分区表」同源，烧录后回读比对 + 复位读串口判「已启动 / 循环重启」。

新增参数：`--mode {idf,staged,diag}`、`--idf-all`（`idf.py flash --all`，关掉 IDF 快速重烧）；
`-y/--yes` 同时跳过方式菜单（非交互式默认仍走 `staged`，不改变既有自动化行为）。

## 为什么反相板不能直接用 `idf.py flash`（实测三条）

1. `idf.py flash` 的 `--before` 来自**编译期**：`components/esptool_py/project_include.cmake:472`
   `set(esptool_flash_main_args "--before=${CONFIG_ESPTOOLPY_BEFORE}")`，值固化在 `sdkconfig`，
   命令行改不了。
2. `--extra-args` 也不行：`serial_ext.py:234` 把参数 `shlex.split` 后放进
   `SERIAL_TOOL_EXTRA_ARGS`，`run_serial_tool.cmake:127` 把它**追加在 `write-flash` 之后**；
   实测 `esptool --chip esp32s3 -p COM18 write-flash --before no-reset ...` 直接报
   `No such option '--before'. Did you mean '--force'?`
3. 这块板 DTR→EN、RTS→GPIO0：esptool 的 ClassicReset 结尾是「GPIO0 拉高 → 再释放 EN」，
   于是芯片**正常启动应用**，日志首字节 `I`(0x49) 被当成包头发 →
   `Invalid head of packet (0x49)`。

结论：改 `sdkconfig` 能解，但那要四个版型全部重编，代价远大于收益。所以走「同一份
`build/flash_args` + 同一条 `write-flash`，只把那次复位换成脚本按正确时序送进下载模式」，
写入内容 / 地址 / 波特率与 `idf.py flash` 完全一致。

## 验证（未碰硬件，真烧录仍由用户执行）

| 项 | 结果 |
|---|---|
| `idf.py --version`（用脚本的 env，`MSYSTEM` 已移除） | `ESP-IDF v6.1-dirty`，rc=0（直接裸跑会只打 MSys 警告且无输出 → 已避开） |
| `idf.py -p COM18 -b 230400 -B build flash --help` | rc=0，`--all` / `--extra-args` 等选项正常列出 |
| `build_idf_command` | `...\venv\python.exe <IDF_PATH>\tools\idf.py -p COM18 -b 230400 -B build flash` |
| 分支演练（拦截 subprocess） | 标准接线 → 走 idf.py；反相 → 打印原因并转单会话，写入地址 `0x0 0x8000 0xd000 0x20000 0x800000`（assets 垫底） |
| `--idf-all` | 命令尾部追加 `--all` |
| `py_compile` / `--help` | 通过 |

## 附带修正

- `_write_all_at_once` 改为**按地址升序**写：app 先落盘，3.9MB 的 assets 垫底，中途断了更可能留下能启动的板子。
- `_idf_env()` 移除 `MSYSTEM`：idf.py 见到它会打警告，且本机在 Git Bash 下出现过「只打印提示就退出、退出码 0」的假成功；即便真出现假绿，后面的回读校验也会兜住。
