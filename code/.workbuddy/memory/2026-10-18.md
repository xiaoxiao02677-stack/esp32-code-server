## 服务端 VAD 回声误打断修复：打断前回声探测（提交 723ce515，生产已部署）

**故障（16:57 生产实录，pending_tts_stop 固件已生效后的新根因）**：两轮播报分别在 16:57:00/16:57:23 被掐（`Abort message received`，且设备日志无 `Send abort speaking` → 服务端发的）。根因链：SERVER_AEC 板 Speaking 态持续推流 → 设备扬声器播报声被麦克风拾取回传 → **服务端 Silero VAD 对原始上行 PCM 直判（代码里根本不存在 AEC 实现，`conn.client_aec` 只是"打断判定在服务端"的开关）** → 连续 2000ms（用户 interrupt_threshold=100）过双阈值+3 帧滑窗 → `_maybe_server_interrupt` 直接 abort。

**关键架构盲区**：echo_guard 只护 startToChat（ASR 文本层），而 `_maybe_server_interrupt` 在 VAD 音频层独立触发——回声在 ASR 出文本**之前**就把播报掐了。且播报期回声让 VAD 持续为真，`client_voice_stop` 永不触发，文本打断路径（startToChat:153 的 handleAbortMessage）在连续播报期间根本没机会执行——所以不能简单关掉 VAD 打断，否则用户失去 barge-in。

**修复（`core/handle/receiveAudioHandle.py`）**：确认窗满足后不再直接 abort，改走 `_interrupt_with_echo_probe`：
1. 取 `conn.asr_audio` 最近 50 帧（3s，VAD/ASR 共享缓存，播报期回声全在里面）
2. `conn.asr.speech_to_text_wrapper` 快速识别（生产 fun_local 本地 SenseVoice，零 API 成本）
3. `_asr_result_to_text` 归一化（**fun_local 返回 dict 取 content**，声纹 JSON 同样取 content——直接 .strip() 会 AttributeError）
4. `check_echo` 判回声：回声→放弃打断继续播；非回声→真人插话照常 abort；空/异常→保守放行
5. 0 档（confirm_ms=0 立即打断）保持原语义跳过探测（保"立即"）

**测试**：`tests/test_interrupt_echo_probe.py` 12 用例全过（回声放弃/真人打断/空文本/音频不足/ASR异常/dict形态/确认窗路由/时序/0档/探测窗 50 帧）；全套件 112 passed 无新增失败（doubao_v3/edge-tts 12 失败为 mock 环境存量，干净 master 复现确认）。
