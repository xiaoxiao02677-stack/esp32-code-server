## 30.9 豆包链路人设不生效根因修复（IDENTITY PRIORITY，测试环境已部署）

**现象**（用户原话："用豆包语音的话, 提示词怎么还不生效了????"）：TTS 从百炼 duplex 切到豆包 TTS_DoubaoV3 后，人设"不管说什么都回答哈哈哈哈"完全不被 LLM 跟随，回复仍是默认文风（"我喜欢的东西挺多的，比如傍晚的风…"）。

**排查链**：
1. 确认豆包是纯 TTS（type=doubao_v3），ASR/LLM 走本地链路（SenseVoice→DeepSeek），与百炼 duplex（LLM 在百炼应用内）机制完全不同
2. 日志实证人设链路全通：差异化配置 prompt 下发 ✓、快速提示词 ✓、增强提示词构建 6006 字 ✓
3. **DeepSeek API 三场景直测（线上真实模板复刻）定位根因**：纯人设 → 回"哈哈哈哈"（人设本身有效）；增强模板+人设 → reasoning 原文暴露冲突"identity says reply 哈哈哈 but core_rules demand actual answers"，人设被 6000 字英文模板的强人格（You are a playful...）+ core_rules（Get to the point）稀释压住
