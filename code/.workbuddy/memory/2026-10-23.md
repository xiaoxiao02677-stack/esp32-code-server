## 25. 17:0x~17:3x dashscope SDK（MultiModalDialog）接入评估：结论"不迁移，按需取协议点"

用户问能否接入官方 SDK 替代手写 WebSocket 实现（"功能更全面，不用摸索"）。
评估路径：读 SDK 源码（multimodal_dialog.py 643 行全读）→ 写探针脚本
`_mm_sdk_probe.py`（服务器 /root/_mm_sdk_probe.py）实测四用例。

### SDK 源码关键事实（dashscope 1.25.2，满足文档要求的 ≥1.24.2）
- **线程模型是同步 threading**（WebSocketApp + 独立线程 run_forever），回调
  从 ws 线程触发；我们服务端是 asyncio → 集成需 run_coroutine_threadsafe
  桥接，每层回调都要包一层，复杂度不降反升
- **保活不是 SDK 托管**：ws 层 ping/pong 自动（5s/4s），但应用层
  send_heart_beat() 不自动发；**静音帧保活（20s 无上行断会话）也不在 SDK
  职责内**——我们手写的静音填充/心跳逻辑必须原样保留
- **无自动重连**：断线要自己重建实例；3 次重试逻辑仍得保留
- **SDK 缺陷两个**：① _wait_for_connection 5s 超时不抛异常，连接失败静默
  继续 → 探针首跑现场复现 WebSocketConnectionClosedException（我们已修的
  静默失败坑 SDK 原生就有）；② _Request.app_id/dialog_id 从不回填，后续
  指令 payload 里这两字段是 None（探针里需手动 dialog.dialog_id=started_id
  workaround 才能用 request_to_respond/interrupt）
- **回调 payload 是整个 response_json**：文本在 payload["output"]["text"]，
  不是 output 节（文档没写，探针踩坑）

### 探针四用例结果（17:1x~17:2x，app mm_8e05…，真应用）
1. 语音正常（"你叫什么名字"）：全要素 PASS——ASR 全量流式（"你叫什么名"→
   全句）、LLM"我叫小云…"、音频 5.0s，事件序列与手写实现一致
2. 语音音乐（"给我放一首音乐"）：**空响应复现**（Thinking→text=''→
