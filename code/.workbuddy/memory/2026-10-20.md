## 任务：OTA 触发 YH 断言崩溃排查（只排查不修码）

### 现象
设备 OTA 到 2.5.2：`Starting firmware upgrade` → `YH: stopped` →
`EspTcp: TCP receive failed: -1` → `YH: SERVER CLOSED CONNECTION` →
`assert failed: xEventGroupSetBits event_groups.c:561 (xEventGroup)` → 重启。

### 根因（证据链闭合）
**UAF（use-after-free）重入崩溃**，链条：
1. 摄像头设备 c4:9e:7e:08:c2:b4 被 pin 到 f3724a22（yh-154tft-wifi 2.5.2）——
   **pin 错了版型**（该设备应是 yh-cam，ota_type 空 → 跨 type 触发 force 下载）
2. application.cc:1767 OTA 前 `YhProtocol::Stop()` → `Disconnect()`（yh_protocol.cc:238）
3. `Disconnect()` 调 `tcp->Disconnect(); delete tcp; tcp_=nullptr;`
4. EspTcp::Disconnect → DoDisconnect(true)：close(fd) 后 **同步调
   disconnect_callback_()**（esp_tcp.cc:100-102，在调用者任务上下文执行）
5. 回调（yh_protocol.cc:170-174）里又调 `Disconnect()`（重入）：此时 tcp_ 已是
   第二次进来……实际是**先 delete tcp 后回调链仍在跑**：DoDisconnect 里
   close 触发 recv 返回 -1 只是巧合时序；关键在 EspTcp 析构
   `~EspTcp(){ Disconnect(); vEventGroupDelete(event_group_); }` 与
   ReceiveTask 尾部 `xEventGroupSetBits(tcp->event_group_, ...)`（esp_tcp.cc:66）
   **竞态**：delete tcp 后 event_group_ 被删/置 nullptr，接收任务退出路径再
   SetBits → configASSERT(xEventGroup) 命中
6. 日志时序佐证：`YH: stopped`（Stop 已执行）→ `TCP receive failed`（接收任务
   还活着）→ `SERVER CLOSED`（回调还在跑）→ assert（SetBits 打到已删句柄）

### 服务端侧事实
- 下载 URL uuid=2c0a5ecf 是临时 token（getDownloadUrl 生成，Redis 3 次上限），
  实体是 f3724a22=yh-154tft-wifi 2.5.2（2945680B，16:28 与 17:17 各下载一次）
- 设备 17:32-17:49 密集 check（每次重启→OTA→崩溃→重启循环），17:45 后平息
  （可能 Redis 3 次下载上限到了返回 404，设备停止升级流程恢复正常）
- **pin 数据错了**：摄像头设备 pin 到 154tft 固件。用户应清 pin 或 pin 到
  yh-cam 正确固件

### 修复方向（待用户确认后实施）
1. **YhProtocol::Disconnect 重入防护**：回调内不再调 Disconnect（或加
   disconnecting_ 标志）；正确顺序=先摘回调再断开
2. **EspTcp 析构竞态**：delete 前先 OnDisconnected(nullptr) 清回调，
   且等接收任务真正退出再删 event_group_（析构里 Disconnect→DoDisconnect(true)
   已等待 ESP_TCP_EVENT_RECEIVE_TASK_EXIT，但被动断开路径 wait=false 竞态仍在）
3. 服务端：清掉 c4:9e:7e:08:c2:b4 的错误 pin（target_ota_id）
