### ★ 踩坑记录（重要，后续部署生产必读）
1. **RewriteValve 两坑**：
   - `setConfiguration()` 在 customizer 阶段调 NPE（内部 `getContainer().getLogName()`，container 未挂载）→ 解法：子类 `ConfiguredRewriteValve` 把 setConfiguration 延迟到 `startInternal()`（此时 container 已挂载），随后 super.startInternal() 找不到 rewrite.config 文件直接 return，预置规则保留
   - `addContextValves` 挂 Context 级**永远不触发**（/xiaozhi/* 按路径映射进不了 /yuhe Context）→ 必须 `addEngineValves`（Engine 级在映射前执行）
2. **Liquibase 校验和漂移**：全仓改名提交（a146e080）误改 7 个已执行 changeset 的 SQL 内容（param_code 'xiaozhi'→'yuhe' 等）→ 启动 Validation Failed → 还原 7 个 SQL 至 faaafaaf 版本（`git checkout faaafaaf -- <files>`）。**教训：改名脚本要豁免 db/changelog/ 历史文件**
3. **壁纸 URL 双坑**：
   - URL 拼接用 `sys_params.server.ota`（非 fronted_url），且 `buildDownloadUrl` 把 `/ota/` 替换为下载路径 → 改 server.ota 即影响新上传壁纸 URL
   - **内容寻址幂等去重只比 version 不比 URL**：同图同版本不同 URL 被"跳过重复入队"挡住，旧 URL 记录在 TTL 内持续补投 → 修 DB 后必须清 Redis 队列键 + 重启 Python（内存队列也持有旧记录）
4. sys_params 已修：`server.fronted_url=https://sandyun.top:8101`（原 http 打 TLS 口 400）、`server.websocket=ws://...:8144/yuhe/v1/`、`server.ota=http://...:8144/yuhe/ota/`；改后删 Redis `sys:params`/`server:config` 缓存键
5. 验证码登录程序化方案：生成 uuid → GET /user/captcha?uuid= → Redis `sys:captcha:{uuid}` 读值（JSON 带引号需 parse）→ sm2.doEncrypt(captcha+password) → POST /user/login；header 是 `Authorization: Bearer`；测试账号 demo（super_admin），token 手工插 sys_user_token（UPDATE 而非 INSERT ON DUPLICATE，主键是 id 非 user_id）
