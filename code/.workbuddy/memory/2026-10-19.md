  构造时从 NVS `display/theme` 读名字（`:81-83`，默认 light）；`SetTheme`（`:1220`）末尾
  `Display::SetTheme` 持久化（`:1361` 注释 "Save theme to settings"）——**切换本来就落 NVS，重启保持**

  light/dark 之外的名字 `GetTheme` 返回 nullptr 直接 false，**不存在第三主题**

  volume/brightness/wake_word(+display/threshold/duration)/interrupt_threshold（board.cc:213-428），

  background_image，assets.cc:361-411）——但这走 **assets OTA**（整包重烧），不是逐设备实时下发

## 02:10 固件编译错误修复（WallpaperKind 前向声明）

**报错**：`application.h:219: error: 'Idle' is not a member of 'WallpaperKind'`
（display.cc 编译失败，ninja 停止）。

**根因**：`enum class WallpaperKind;` 前向声明是不完整类型，**不能用于默认参数**
`WallpaperKind kind = WallpaperKind::Idle`——默认参数需要枚举值的完整定义。
两处同款问题：`main/application.h`（SendWallpaperAck）与 `main/yh/yh_protocol.h`
（SendWallpaperResult）。

**修复**：两处前向声明均改为 `#include "wallpaper/wallpaper_manager.h"`。
wallpaper_manager.h 只依赖标准库（cstddef/functional/string），无循环依赖风险。
已同步测试树 `hardware/sets_test_envirment/yuhe-esp32/main/` 同两文件
（diff -rq 仅剩 sets-build.json 生成残留，正常）。

**编译验证**：完整 `idf.py build` 通过（PowerShell），产出
`build/yuhe.bin 0x2ce280B`，app 分区剩 29% 空闲。注意 GBK 控制台下 bat 中文
注释乱码、Git Bash 下 idf.py 假绿（rc=0 提前退出）——校验必须 PS/CMD。
环境变量全套（IDF_PATH/IDF_TOOLS_PATH/IDF_PYTHON_ENV_PATH/ESP_IDF_VERSION +
cmake/ninja/xtensa/bin PATH），`ESP_IDF_VERSION` 必补（idf_component_manager
对 None 做 Version.coerce 会崩）。ninja 实际路径多一层版本目录

永远参数错。最终弃用，老老实实跑完整 build。
