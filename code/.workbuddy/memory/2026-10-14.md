## 01:00 - 订单管理 404 根因定位与全链路修复（重要）

### 根因（三个连环坑，此前 3 个 agent 全部误判）
1. **jar 未真正部署**：`mvn package` 产物在 `/root/yh/app/manager-api/target/xiaozhi-esp32-api.jar`，
   但 systemd unit 跑的是 `/root/yh/deploy/opt-xiaozhi/xiaozhi-esp32-api.jar`。
   **改完代码只 restart 不 cp = 白改**。部署必须两步：`cp target/*.jar /root/yh/deploy/opt-xiaozhi/` 再 restart。
2. **context-path 双前缀（最关键）**：`application.yml` 里 `server.servlet.context-path: /xiaozhi`，
   而 OrderController 写了 `@RequestMapping("/xiaozhi/order")` → 真实路径变成 `/xiaozhi/xiaozhi/order/*`。
   项目内其他 Controller 都是 `@RequestMapping("/user")` 这种**不带 /xiaozhi 前缀**的写法。
   验证方法：`curl /xiaozhi/xiaozhi/order/page` 能返回数据即证明双前缀。
3. **401 ≠ 端点存在**：鉴权拦截器对所有路径生效，未注册的路径无 token 也返回 401，
   导致此前 agent 误判"端点已注册只是缺 token"。**判断端点是否注册必须带有效 token 看是 200 还是 404**。
