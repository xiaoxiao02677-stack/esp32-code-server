## 日志轮转 + nginx proxy_protocol 真实 IP（已上线）

### 1. 日志：改追加 + logrotate
排查结论：**`>` 覆盖写已不存在**（10-09 WS 修复时两个 unit 都改成 `StandardOutput=append:`；无 .sh 启动脚本；loguru 本身默认 append）。

→ 新建 `/etc/logrotate.d/xiaozhi`：daily / rotate 14 / maxsize 200M / compress / dateext / **copytruncate**。
**必须用 copytruncate 不能用默认 create**：systemd 持有 fd，create 会 rename 旧文件，systemd 继续写旧 inode → 新文件永远空、旧文件继续膨胀。copytruncate 原地截断，fd 不变。
`tmp/server.log` 不纳入（loguru 自己 10MB 轮转 + 30 天保留，会和 logrotate 抢文件）。
实测：轮转后 15s 内 app.log 9784→15862B，服务持续写入，fd 没断。

### 2. nginx proxy_protocol 打通真实 IP
链路：设备 → stream:8001 → http:9001 → Python:8000。http 层看到的对端是 127.0.0.1 → X-Real-IP 全是 127.0.0.1。
**Python 侧早支持**（connection.py:212 读 x-real-ip/x-forwarded-for），代码一行没改，纯 nginx 配置问题。

方案：stream 加 `proxy_protocol on`；新增 **127.0.0.1:9002 / 9444**（listen 带 proxy_protocol + set_real_ip_from 127.0.0.1 + real_ip_header proxy_protocol），stream map 改指过去；**旧的 9001/9443 完全不动**，便于秒回滚。
为什么不用 9001/9443 直接加 proxy_protocol：它们是公网直连端口，实测有 censys/infrawat.ch/modat.io/Go-http-client 扫描流量，开了会让所有非 PROXY 头的直连握手失败。
